UTeM SOC Phishing Detection System

Intelligent Management Framework for Mitigating Social-Engineered Spam and Cyber Threats in University Social Groups

Real-time WhatsApp Monitoring with Machine Learning

Problem Statement

University social groups (WhatsApp, Telegram) are primary infrastructure for student communication at Malaysian universities. These high-trust environments are exploited by social engineering attacks that impersonate university officials or student representatives, bypassing conventional security filters.

  • Operational Bottlenecks: The 24/7 nature of social media makes manual moderation nearly impossible, resulting in excessively high response delays during periods of high phishing activity
  • Language Circumvention: Malicious actors use local slang and code-switching (Malay-English hybrids / Manglish) to avoid detection by standard English-centric keyword filters
  • Subjective Decision-Making: The lack of a standardized framework leads to inconsistent management practices, with different moderators handling similar threats differently
Project Objectives
  • Objective 1: To develop a localized threat intelligence dataset and benchmark machine learning algorithms (Random Forest vs. SVM) for detecting social-engineered attacks in Malaysian higher education social groups
  • Objective 2: To design and implement a web-based proactive management framework that automates risk-based response protocols for social group administrators
  • Objective 3: To evaluate the integrated framework using detection accuracy, false-positive rate, response latency, and automated warning delivery in a controlled university social-group environment
Project Scope

Data Domain & Platform

  • Text-based social engineering threats in WhatsApp & Telegram at Malaysian universities
  • Phishing links, fraudulent tuition payments, scholarship scams, and urgent account-update messages

Language Focus

  • English, Malay, and Manglish / Malay-English code-switching
  • Designed to address gaps in standard English-centric filters

Technical Implementation

  • Python ML with Random Forest & linear SVM benchmarking
  • FastAPI, Jinja2 templates, JavaScript, and WebSockets dashboard
  • Proactive decision support through risk scoring and response recommendations

Exclusions

  • No image-based detection (OCR), deep packet inspection, or hardware-level security

Dataset Preparation & Validation

Dataset Preparation Controls

  • Acquisition: Use approved public, anonymized, or synthetic English, Malay, Chinese, and mixed-language university scam messages
  • Cleaning: Remove duplicates, empty rows, identifiers, and label errors
  • Splitting: Apply a stratified train/test split with a fixed random seed

Validation Evidence

  • Record dataset source, licence, version, and class balance
  • Fit TF-IDF on training data only to prevent information leakage
  • Evaluate RF and SVM on the same held-out partition for fair comparison
  • Replay controlled messages through the full Selenium-FastAPI-dashboard workflow
Preprocessing Pipeline
Figure 4.3: Data preprocessing pipeline — raw WhatsApp messages pass through lowercasing, URL/emoji removal, bilingual stop-word filtering, tokenization, and TF-IDF vectorization to produce numeric feature vectors for the classifier
Machine Learning Models

Random Forest (Primary)

  • Uses TF-IDF and engineered risk features from preprocessed short messages
  • Robust for noisy informal text and non-linear feature relationships
  • Supports model comparison and feature transparency for administrator review

Linear SVM (Benchmark)

  • Well-established baseline for high-dimensional sparse text classification
  • Uses the same partitions and TF-IDF representation as Random Forest
  • Provides the report's accuracy-latency comparison against the primary model

Design rule: The final model choice is justified by accuracy, precision, recall, F1-score, false positives, response latency, warning delivery, and stability evidence.

System Architecture

Threat Detection Sequence
Figure 4.4: Threat detection and mitigation sequence — seven-step operational flow: (1) new message appears in WhatsApp Web, (2) Selenium radar detects and POSTs the payload, (3) FastAPI sends text to ML engine for vectorization and classification, (4) ML engine returns label and confidence score, (5) backend pushes live status to dashboard via WebSocket, (6) mitigation command is returned to Selenium, (7) if risk exceeds threshold, an automated warning is injected into the chat
Risk Scoring & Mitigation Logic

Classification Inputs

  • Incoming WhatsApp message text, sender metadata, timestamp, and source group context
  • Preprocessing applies normalization, stop-word filtering, tokenization, and TF-IDF vectorization
  • Learning engine returns Safe or Threat label with confidence score

Mitigation Response

  • Backend compares prediction probability with the selected threat threshold
  • Safe messages update the dashboard without posting a WhatsApp response
  • Threat messages return a mitigation directive to Selenium
  • Selenium posts a localized warning and the event remains visible for administrator review

Testing & Evaluation Strategy

Model-Level Evaluation

  • Accuracy: Overall prediction correctness
  • Precision: Reliability of threat warnings
  • Recall: Ability to detect actual threats
  • F1-score: Balanced model effectiveness when classes are uneven

Integrated-System Evaluation

  • Verify WhatsApp Web extraction through Selenium WebDriver
  • Confirm FastAPI classification, event persistence, and WebSocket dashboard updates
  • Measure false-positive rate, response latency, automated warning delivery, and stability
  • Use anonymized or synthetic university-scenario messages in a controlled setting
Implemented Modules & Tech Stack

Implemented Modules

  • FastAPI app coordinates routes, monitor state, manual analysis, review, and warning endpoints
  • Learning engine normalizes multilingual text, extracts signals, builds TF-IDF features, and trains RF/SVM
  • Risk-event repository stores classified events for dashboard history and review
  • WhatsApp radar controls Selenium, reads messages, submits classifications, and sends warnings

Tech Stack

  • Python 3.10+ / FastAPI / Uvicorn / Jinja2
  • Scikit-learn, Pandas, NumPy, TF-IDF, Random Forest, linear SVM
  • Selenium WebDriver / ChromeDriver / WhatsApp Web DOM monitoring
  • SQLite persistence, WebSockets, HTML5, CSS3, and JavaScript dashboard
